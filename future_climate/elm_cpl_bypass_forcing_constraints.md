## 1. 索引机制:硬编码的绝对年份偏移,不读文件的 time 坐标

CO2/Ndep 不像 met 那样可以按文件自身的起始年对齐,而是把"模拟年份"直接代入写
死在源码里的公式换算成数组下标,**完全不管文件里 time 变量的实际取值**:

| 强迫 | 公式(源码位置) | 隐含要求 | clamp 范围 |
|---|---|---|---|
| CO2 | `nindex = yr - 1764`(`lnd_import_export.F90:1297`) | 文件第 1 条记录必须是 **1765 年** | 1850–2100,超界复用边界年 |
| Ndep | `nindex = yr - 1848`(`lnd_import_export.F90:711` / `861`) | 文件第 1 条记录必须是 **1849 年** | 上限 clamp 在 168 → **2016 年**,之后一直复用 2016 年的值 |

**结论:这两类文件都不能只做"从 2024 年开始"的新文件。** 如果只把 2024-2100
的数据放在文件开头(数组位置 1),代码查 2024 年时用的下标是 `2024-1764=260`
(CO2)或 `2024-1848=176`(Ndep),会读到从未写入过的数组位置(初始化值
spval)——**不会报错,直接读到脏数据**,非常隐蔽。

**正确做法**:不新建文件,在原来一直用到 2023 年的历史文件**末尾续接**未来
情景数据,做成一份从 1765(CO2)/1849(Ndep)连续到目标年份的单一文件,位置
不能断开。

Ndep 还多一层限制:就算续接对了,2016 年之后的 clamp 上限(`168`)会让代码
一直复用 2016 年那年的值,不会真正读取续接进去的未来 Ndep——这是源码里一行
硬编码的 bug,不是设计如此,要用真正的未来过渡态 Ndep 必须先改这一行。

## 4. met bypass 最近邻映射:20 个陆地格点落在无效 TESSFA 格上(2026-08-14 已核实,决定不处理)

和 §1-3 的 CO2/Ndep 年份索引问题不是一回事,是 met(气象)bypass 自己的坑,发生
在**空间映射**而不是时间索引上。已针对 `20260723_Southeast_hires_s7P_s8hdmfix_
harvfix_ICB20TRCNPRDCTCBC` 这个已完成的历史 run 直接核实过。

### 机制

`metdata_bypass` 目录下的 `zone_mappings.txt` 把 TESSFA 网格全部 225,625 个点
(含海洋/无效格)原样列出,`lnd_import_export.F90` 里给每个陆地格点选气象强迫
点时,只做纯经纬度最近邻搜索,**不检查目标点是不是有效数据**:

```fortran
thisdist = 100*((latixy(g3)-ldomain%latc(g))**2+(longxy(g3)-ldomain%lonc(g))**2)**0.5
if (thisdist .lt. mindist) then
  mindist = thisdist; ztoget = zone_map(g3); gtoget = grid_map(g3)
end if
```

这个映射在模拟一开始算好后**整个 run 期间固定不变**——如果某个陆地格点的最近
TESSFA 点恰好是无效格(哨兵值,见 §"int16 哨兵值"相关讨论),这个陆地格点从
1850 到 2023(或任意历史时段)**全程**都在用哨兵值解码出的假气象数据跑模式,
不是偶尔出错。

### 核实结果(domain.nc: `20260712_.../run/domain.nc`,75,920 个陆地格点)

- **75,900 个(99.97%)** 最近邻精确对应有效降水格
- **20 个** 最近邻精确落在哨兵格上(用 `TBOT<350K` 判定有效性,和 `tessfa_
  mask.py` 同一套规则),全部在海岸线/河口附近(佛罗里达东岸、路易斯安那三角
  洲、南卡莫特尔湾、北卡外滩群岛等),网格错位(TESSFA 中心对齐 vs domain 边
  对齐,差半格 ~0.0295°)导致
- 拿这 20 个点在 2023 年 h0 输出里查 `GPP`/`TOTSOMC`:
  - **5 个是真正的"死格"**(GPP 恒为 0,TOTSOMC 只有 0.05~79 gC/m²,比域内均值
    17753 低 2-4 个数量级):`(nj,ni)=(54,358)`、`(55,358)`、`(216,370)`、
    `(237,399)`、`(237,400)`
  - 其余 15 个 GPP/TOTSOMC 落在域内正常范围——同样在用哨兵数据,但映射到的具体
    无效格解码出来的数值没有极端到把模式逼死

### 决定(2026-08-14):不处理

20/75,920 = **0.026%**,对域平均/聚合统计可以忽略,用户判断不值得为此改代码或
重做映射。**这是用户的决定,理由站得住脚**——仅在以下情况需要重新想起这件事:

- 做**逐格点**分析(沿海碳通量热点图、验证具体站点、挑单点画时间序列),尤其是
  涉及上面这 5 个坐标附近时,必须手动排除,否则会被误读成"这里是真实贫瘠地"
- 以后重新生成 `zone_mappings.txt` 或换新强迫数据源时,值得在最近邻搜索前先用
  类似 `TBOT<350K` 的规则过滤掉无效候选点,从根上避免

**How to apply**:域尺度/聚合类工作不用管这件事;涉及这 5 个具体坐标的逐格点结
果要重新核实是不是又踩到这个问题。

## 5. Ndep 2016 冻结:实测确认 + 真实偏差量级 + CO2 对比结论(2026-08-14)

### Ndep 确实被冻结,已用真实输出验证

在 `20260723_Southeast_hires_s7P_s8hdmfix_harvfix_ICB20TRCNPRDCTCBC` 这个跑到
2023 年的历史 run 里,从 h0 输出取 `NDEP_TO_SMINN` 逐年域平均:2016-2023 连续
8 年数值精确相同(0.782 gN/m²/yr,精确到小数点后 6 位),2005-2015 逐年都在变
——和 §1 里代码分析的 `nindex clamp 在 168 → 2016 年` 完全吻合,不是理论推测。

又直接从实际配的 Ndep 源文件(`fndep_elm_cbgc_exp_simyr1849-2101_1.9x2.5_
ssp245_c240903.nc`,本身覆盖到 2101 年)里读出 2017-2023 年**真实**该有的值,
和被冻结用掉的 2016 年值对比:

| 年份 | 真实 Ndep(gN/m²/yr) | 相对 2016(冻结值)偏差 |
|---|---|---|
| 2016(冻结基准) | 0.782 | 0% |
| 2017 | 0.774 | −1.0% |
| 2018 | 0.696 | −11.0% |
| 2019 | 0.735 | −6.0% |
| 2020 | 0.722 | −7.7% |
| 2021 | 0.709 | −9.4% |
| 2022 | 0.680 | −13.1% |
| 2023 | 0.704 | −10.0% |

真实趋势持续下降,冻结在 2016 年的值相当于系统性**高估** 2017-2023 年 N 沉降
1%~13%(多数年份 6%~13%)。文件本身数据是够的,纯粹是代码 clamp 把它挡住了。

### 要不要重跑历史 run:用户待决策,倾向不整段重跑

只影响 173 年里最后 7 年(4%),偏差量级个位数到十几个百分点,且碳循环对 Ndep
偏差的响应通常被削弱(N 沉降不是唯一氮供给来源)。**不建议整段重跑 1850-2023**
——性价比太低。更划算的路径:改完 §1 提到的 clamp 那两行之后,从 2015/2016 年
附近的 restart 分支**只重跑 2016(或2017)-2023 这 7-8 年**,成本远低于整段重
跑,而且这个代码改动为了 future simulation 本来就要做,顺手就把历史尾巴也修了。

真正决定因素:下游分析是否具体用到 2017-2023 的结果(比如对比近期通量观测、或
这几年是未来情景分支的基准期)。如果是,值得花这个小成本重跑;如果这段历史 run
主要是给未来模拟提供一个 spinup 好的起点,不用管。

### CO2 没有同样的问题——已实测验证

CO2 的 clamp 上限对应 **2100 年**(`nindex = min(max(yr,1850),2100)-1764`,
生产代码 `lnd_import_export.F90:1447`),这次历史 run 只到 2023 年,离上限还
有 77 年,不会触发。用同样方法从 h0 输出取 `PCO2` 逐年域平均验证:

```
1850: 280.2 ppm   2000: 363.3 ppm   2016: 395.9 ppm   2020: 404.6 ppm
1900: 291.1 ppm   2010: 382.5 ppm   2017: 397.8 ppm   2021: 406.9 ppm
1950: 305.8 ppm   2015: 393.8 ppm   2018: 400.4 ppm   2022: 409.2 ppm
                                    2019: 402.3 ppm   2023: 410.9 ppm
```

逐年持续平滑上升,1850 年 280 ppm 吻合公认工业化前基准值,2016 年前后**没有任
何断点或冻结**——和 Ndep 完全不同,不需要做任何处理。

**结论对比**:同样是"硬编码年份 clamp"这个代码模式,Ndep 因为 clamp 上限
(2016)早于这次历史 run 的结束年(2023)而实际触发、造成了 7 年的数据冻结;
CO2 因为 clamp 上限(2100)远晚于 2023 而完全没有触发。**两者是否需要处理不能
一概而论,要看 clamp 上限和实际跑的年份范围的相对位置**——以后接手任何用到
CPL_BYPASS 的年份区间强迫(不只是 CO2/Ndep),都要照这个方法先查 clamp 上限对
应哪年、再看有没有真的跑过界,不能只看代码逻辑就下结论,最好像这次一样拿实际
输出核实一遍。

**How to apply**:Ndep 重跑与否是用户尚未最终拍板的决定,读到这条时先确认是否
已经做出选择、是否已经重跑;CO2 部分已确认无需任何行动。
