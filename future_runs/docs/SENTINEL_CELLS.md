## 结论摘要

**机制**：cpl_bypass 的最近邻匹配**不检查匹配到的气象点是否有效**
（`lnd_import_export.F90`，代码见 §4）。zone_mappings 覆盖含海洋的整个
气象矩形，海洋行存的是各变量的 sentinel，于是最近邻落到海洋侧的陆地格点
静默拿到 sentinel。

**范围已用两条独立路径交叉确认**：194 个格点，见 §0。

**影响**：这些格点**在错误驱动下当前模拟出的通量贡献接近零**——GPP 恒为 0，
生物量是域均值的万分之一量级。**但这不等于"影响为零"。** 脚本算的是
"错误驱动下它们产出了什么"，没有算"用正确气象它们本该贡献多少"。
死区恰恰说明**局地影响极大**；域总量层面的反事实损失需要修正后的对照
试验或合理估算才能确定，目前**未知**。§6 给出一个基于邻近干净格点的
初步估计，但那是 2026-08-21 别处工作的结论，不是本次测量。

## 4. 为什么会匹配到无效点 —— 匹配不检查有效性

`lnd_import_export.F90` 对每个 ELM 格点在 zone_mappings 的 225,625 行里按
度数欧氏距离找最近点，**没有任何"该点是否有数据"的检查**：

```fortran
do g3 = 1,ng
  thisdist = 100*((latixy(g3) - ldomain%latc(g))**2 + &
                  (longxy(g3) - ldomain%lonc(g))**2)**0.5
  if (thisdist .lt. mindist) then
    mindist = thisdist ; ztoget = zone_map(g3) ; gtoget = grid_map(g3)
```

**⚠️ 初版在这里给出的匹配距离统计已作废。** 那组数字用的是 h0 输出的
`lat`/`lon` 坐标数组，而模型用的是 `domain.nc` 的 `xc`/`yc`（经
`ldomain%lonc/latc`）。用正确坐标重做后（job 516143）：

```
平局多重度: min 1  中位数 1  max 1      有平局的格点: 0 / 194
```

**没有任何平局**，所以初版"两套网格恰好偏移半格、每个格点都是四路平局"
的说法**是错的**，一并作废。仍然成立的是代码事实：匹配不检查有效性。
偏移的确切几何**尚未用正确坐标重新测量**。

初版另一处措辞问题：所谓"随机抽样的 4,218 个活跃格点"实际是**固定步长的
系统抽样**（`np.arange(0, n, n//4000)`），不是随机抽样。

## 5. 七个变量里哪些是 sentinel

**用 `domain.nc` 的 `xc`/`yc` 重做匹配后（job 516143）：TBOT sentinel
命中 194 / 194。**

下表是初版用 h0 坐标匹配的结果（182/194），保留以说明差异来源——那 12 个
"未命中"完全是坐标来源错误造成的，不是第二种机制。在第一条 2024 真实
记录上，按**原始短整型**比较：

| 变量 | 原始 sentinel | 解码后 | 命中 |
|---|---|---|---|
| TBOT | 22725 | 396 K | 182 / 194 |
| PSRF | −23831 | −9999.1 Pa | 182 / 194 |
| QBOT | −14592 | 0.0010156 | 182 / 194 |
| FSDS | −30984 | −1111 W/m² | 182 / 194 |
| PRECTmms | −32768 | −0.088 | 182 / 194 |
| WIND | −14600 | −0.00134 | 182 / 194 |
| FLDS | 14924 | 1001 W/m² | 182 / 194 |

```
七个变量全部 sentinel : 182 个格点
任意一个 sentinel     : 182 个格点
```

两个数相同：**要么整行是海洋（七个全 sentinel），要么整行有效**，没有中间态。
TBOT 解码后 396 K 被 `min(...,323)` 钳成 323，PSRF 解码 −9999 Pa 被
`max(...,40000)` 钳成 40000——与实测的钳位现象吻合。

**那 12 个已解释（2026-09-08）**，过程记录如下，因为中间两步的结论都是错的：

1. 初版：12 个在 record 2920 上不是 sentinel，未解释。
2. 扩大到记录窗口 [2912, 2952) 后显示"future 侧 194/194 在某记录上全 sentinel"
   ——**这是假象**，窗口跨进了 dummy 年（记录 1–2920），dummy 年按设计
   处处是 sentinel（job 516108/516109）。
3. 怀疑 dummy 尾修复漏了这 12 行——**证伪**：`rec2920 == rec2921` 全部 12/12，
   解码值 284–298 K 正常（job 516126）。
4. **真正原因**：我用 h0 的 `lat`/`lon` 而非 `domain.nc` 的 `xc`/`yc` 做匹配。
   换成正确坐标后 194/194 全部命中 sentinel（job 516143）。

**结论：194 个全部是 sentinel 格点，没有第二种机制。**

**GPP 恒为 0，TOTVEGC 是域均值的 1/64000。** 这些格点没有植被、没有生产力——
在 323 K / 40 kPa 的驱动下植被无法存活。

**这张表只说明一件事：在错误驱动下，这些格点当前产出接近零。**
它没有回答"用正确气象它们本该贡献多少"。

## 7. 待决策（不由本文件决定）

三条路，代价差别很大：

**(a) 改 `lnd_import_export.F90` 的最近邻匹配**，让它跳过 sentinel 行。
代价：源码改动要重新走 T1/T2 级别的验证；**并且会改变历史运行的结果，
A3 初始场随之作废，历史要重跑**。

**(a′) 不改源码，只过滤 `zone_mappings.txt`**：生成一份只含有效气象候选点
的映射表，zone 仍为 1，`grid_map` 保留原始全局索引。Fortran 按文件实际行数
读候选点，于是现有最近邻算法**自然选到最近的有效点**，无需任何 SourceMods。
比 (a) 小得多也容易审计。**尚未构造，也尚未离线 QA。**
待核实的关键前提：历史与全部 future 情景是否使用同一份稳定的有效掩膜；
以及采用它究竟只需重跑 transient，还是连 AD spinup / 后续 spinup 也要重跑。

**(b) 把这 194 个格点从 ELM 域里屏蔽掉**。改 domain 文件。
代价：活跃格点数从 75,920 变化，**A3 初始场同样作废**，历史要重跑。

**(c) 接受并明确记录**：0.2341% 的陆地面积、全部位于海岸/域边界、
对所有通量总量贡献 0.0000%，在分析和出图时排除这 194 个格点。
代价：零重跑，但每一张图、每一个区域统计都要带这个排除说明。

**(b) 暂不考虑**（用户 2026-09-08 决定）：它会删掉多数 `LANDFRAC=1` 的
真实陆地格点，并改变 domain/restart 结构。

**共同的硬约束**：(a)、(a′)、(b) 都会改变模型读到的驱动，因而作废已验收的
A3 初始场并要求重跑；**重跑范围取决于 spinup 是否也用了同一映射，未查清**。
(c) 不需要重跑。

**当前状态：不在 (a′) 与 (c) 之间拍板**，等补证完成。

## 第一版（516078）的错误，保留记录

第一版第 5 节报告"七个变量 sentinel 命中 0 / 194"，是错的。
netCDF4 读取时默认套用 `scale_factor`/`add_offset`，而 sentinel 是**原始
短整型**，拿原始值去比已解码的浮点必然全 False。讽刺的是同一行打印的样本
里就有解码后的 sentinel（PSRF −9999.086、FSDS −1111.027、PRECTmms −0.088、
WIND −0.0013428、QBOT 0.0010156）——检查说干净，它自己的证据说不干净。
已修（`set_auto_maskandscale(False)`，并同时打印原始值和解码值以便肉眼复核）。
第 1–4、6 节不受该 bug 影响。
