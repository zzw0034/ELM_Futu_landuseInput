## 它推翻了 T1b 的"相位重置"结论

T1b 报告：重启把七个变量的相位重置，FSDS/PRECTmms 在段边界前跳一条记录，
因此分段不会与连续逐位相同。**这是错的。**

**错因**：那里拿 leg1 的**最后一步（2024-01-03 tod_h=0）**去比 leg2 的
**第一步（tod_h=1）**——**相差一小时**，索引本来就该不同。

按**同一模式时刻**重新对齐：

```
2024-01-03 tod_h=1
  T1c 连续        call=49   v=1..7 全部 (2936, 2937)
  T1b leg2 初始化  call= 1   v=1..7 全部 (2936, 2937)     ← 相同
```

而且在连续运行里，tod_h=1 这一刻七个变量本来就同相；相位分裂要到 tod_h=2
才出现（`v=1,2,3,6,7 → (2937,2938)`，`v=4,5 → (2936,2937)`），
两边同样如此。**根本不存在可被重置的相位差。**

## 两条方法论教训

1. **跨重启比较必须按模式时刻对齐**，不能按"最后一步 / 第一步"对齐。
2. **索引观察不构成结论。** 必须有状态层面的数值比对。T1b 里"索引跳了一条
   记录"看起来是硬证据，实际上连现象都不存在。

## 范围限定

逐位相同这一结论只覆盖：**3 个模式日、1 个中断点、中断在日界（tod=0 写出、
tod_h=1 恢复）、10 节点布局**。

**不能外推到**七个正式 run 的 77 年 / 多个段边界，也不能外推到别的 PE 布局
或非日界中断。那是最终布局下完整 T3 的任务。

未实测**——本次中断在日界，没有触及那条路径。
